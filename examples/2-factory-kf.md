## Job
Turn raw feedstock into published, retrievable knowledge — the five-engine line
**Capture → Process → Interconnect → Retain → Produce**, each with one job, one
owner, one gate, one output home.

## Input → Output
Raw feedstock → **nine artefact types, one output home each.** This table is the
factory's output inventory; each engine card owns its slice, each artefact card
owns the rules.

| output | engine | durability | card |
|---|---|---|---|
| Idea | capture | authored | `artefact/idea-note` |
| Inbox note *(in transit, not a product)* | capture | raw | `artefact/inbox-note` |
| Concept note *(+ the MOC patches that file it)* | process | authored | `artefact/concept-note` |
| Map of Content | interconnect | authored | `artefact/moc` |
| Diagram | interconnect | **derived** | `artefact/diagram-file` |
| Flashcards | retain | **derived but stateful** | `artefact/flashcard-file` |
| Pattern | produce | authored | `artefact/pattern` |
| Solution | produce | authored | `artefact/solution` |
| Decision | produce | authored | `artefact/decision` |

**Durability is the operative property** — it decides what may be regenerated.
*Authored* artefacts are patched surgically and never overwritten. *Derived* ones
are deleted and rebuilt freely: a diagram is the one file in the vault
where a full overwrite is correct on every run. **Flashcards are the exception
that bites** — derived, but once synced they carry Anki review history, so a
naive rebuild destroys it.

**Not factory output:** the vault index, the manifests, the health and gaps
reports, and the governance views. Those are machine state the factory *runs on*,
regenerated by script and owned by no engine.

## Owner / Halt Point
**The human owns judgement; the agent owns consistency.** Human halts: merges,
promoting a draft to `final`, MOC creation (the 4+ threshold), and Produce
sign-off. The agent never crosses any of those.

## Contract
- **Index-first.** Agents read the index, not the vault; the freshness
  gate blocks a stale run.
- **Never invent** — every derived claim originates in a source
  note.
- **`final` concept notes are locked**, with exactly three
  permitted patches.
- **Surgical changes only** — the diff is part of the audit
  trail.
- Cadence: weekly run, 40–60 notes per run.
- Loops: **fast** per write (note validation) · **medium** per run (eval) ·
  **slow** per period (measured drift).

## Gate
`GATE-KF-01` (note validation, block + quarantine before every vault write) ·
`GATE-KF-02` (index freshness). Per-engine gates:
`GATE-KF-04` (diagram connectivity) · `GATE-KF-05` (flashcard authoring) ·
`GATE-KF-06` (pattern) · `GATE-KF-07` (frontmatter/body consistency) ·
`GATE-KF-08` (solution) · `GATE-KF-09` (decision) · `GATE-KF-10` (liveness) ·
`GATE-KF-11` (overlap audit) · `GATE-KF-12` (concept body links) ·
`GATE-KF-13` (quotes verbatim) · `GATE-KF-14` (capture fidelity) ·
`GATE-KF-15` (source breadcrumb) · `GATE-KF-16` (example against source).

## Examples
Worked deliverables from Produce — the Knowledge Factory deck is itself one.
Per-engine exemplars live on the engine cards; per-type exemplars on the artefact
cards.

## Auto-fix
**No self-heal** — a failing write is quarantined, not patched. Engine-level
auto-fix is capped and logged where it exists at all (`kf/produce` only, for
mechanical link/frontmatter fixes).

## Log
- **Run record** — pair of git audit commits + a health report
- **EVAL_LOG** — one narrative entry per run (the factory root writes it)
- **Git** — the run's open/close audit commits
- **When** — start and end in-run; eval at the run retro

## Drift Compare
Quality-verdict proportions per unit + example-set age (medium loop); measured drift per
period (slow). Results route to eval as findings, never verdicts.
